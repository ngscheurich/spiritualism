## Question

What does Pi (pi.dev) expose for embedding or driving it from another program? Capture: how it is installed and run; whether it offers a library/SDK, a headless or non-interactive mode, and structured output; how sessions persist and resume; how tools and permissions are configured; what model providers it supports; license and maturity. Primary sources only: official docs and source.

## Context

Findings branch: `research/pi` (never merged). Findings file on that branch: `docs/research/pi.md`.

## Answer

- Identity: pi.dev is the site for Pi, "a minimal agent harness" by "Earendil Inc. & Contributors". Repo `earendil-works/pi`; npm package `@earendil-works/pi-coding-agent` (the former `@mariozechner/pi-coding-agent` is deprecated in its favour). The findings infer, without a single source stating it, that Pi began as Mario Zechner's `pi-mono`.
- Install and run: `curl -fsSL https://pi.dev/install.sh | sh` (macOS/Linux), a PowerShell installer (Windows), `npm install -g --ignore-scripts @earendil-works/pi-coding-agent`, or Nix. Requires Node.js >=22.19.0. Binary is `pi`; standalone binaries are built with `bun build --compile`. Run `pi` from the project directory; the working directory "controls project configuration, resource discovery, and session grouping". An official Docker example exists (`node:24-bookworm-slim`, volume for `/root/.pi/agent`).
- Library/SDK: TypeScript/JavaScript only; `@earendil-works/pi-coding-agent` "embeds Pi in a Node.js or Bun process". `createAgentSession()` returns a `session` with `prompt()`, `steer()`, `followUp()`, `abort()`, `waitForIdle()`, `subscribe()`, `dispose()`; configurable `model`, `thinkingLevel`, `tools`, `customTools`, `sessionManager`, `resourceLoader`, and others. The CLI's `codemode`, `tool_search`, and MCP extensions are not loaded by SDK sessions by default. No Python or other-language SDK was found; docs point other languages to RPC mode. Exact method signatures are unverified.
- Headless modes: Print (`pi -p "..."`, final text on stdout, one invocation; `error`/`aborted` stop reason gives a nonzero exit), JSON (`pi --mode json "..."`, JSONL session events on stdout, one invocation; a failed response does not by itself set a nonzero exit), RPC (`pi --mode rpc --no-session`, strict JSONL commands on stdin and responses/events on stdout, long-lived). When stdin or stdout is redirected and neither JSON nor RPC is selected, Pi uses print mode.
- RPC details: 33 documented commands (`prompt`, `steer`, `follow_up`, `abort`, `new_session`, `switch_session`, `fork`, `get_state`, `get_messages`, `set_model`, `compact`, `bash`, `export_html`, and others). Commands carry an optional `id` echoed in the response; close stdin for orderly shutdown; a `prompt` response's `success: true` "does not mean model work completed", completion is the `agent_settled` event. A typed subprocess `RpcClient` (with `promptAndWait`) is exported and "requires a path to a runnable Pi CLI". Extension UI dialogs are forwarded over an RPC subprotocol; "JSON and print modes have no UI".
- Structured output: JSON and RPC modes emit a typed event stream (`agent_start`, `message_update` deltas, `message_end` authoritative, `tool_execution_end` with `result`/`isError`/`durationMs`, `agent_settled`, and more); JSON mode's first record is a session header `{"type":"session","version":3,...}`. JSON mode is "structured event output, not a single JSON result". No flag was found that constrains the model's final answer to a JSON schema (unverified whether one exists); the documented pattern is a custom tool whose `execute()` returns `terminate: true`.
- Sessions: JSONL under `~/.pi/agent/sessions/--<path>--/<timestamp>_<session-id>.jsonl`, grouped by working directory; override with `--session-dir`, `PI_CODING_AGENT_SESSION_DIR`, or the `sessionDir` setting. Entries form a tree via `id`/`parentId`; format version 3, v1/v2 auto-migrate. Resume flags: `-c/--continue`, `-r/--resume`, `--session <path|id>`, `--session-id <id>`, `--fork`, `--no-session` (in-memory, not resumable). SDK `SessionManager` (`inMemory`, `create`, `continueRecent`, `list`, `open`); RPC `new_session`, `switch_session`, `fork`, `clone`. Resume restores model and thinking level. Automatic compaction near the context limit.
- Tools and permissions: default tools `read`, `bash`, `edit`, `write`; other built-ins `powershell`, `grep`, `find`, `ls`; selection via `-t/--tools`, `-xt`, `-nbt`, `-nt`, `--no-mcp`, or `defaultTools` setting. Pi has no built-in permission system: "By default, it runs with the permissions of the user and process that launched it" and "does not ask for approval before every tool call." Gating is done by extensions whose `tool_call` handler returns `{ block: true, reason }`; the shipped `permission-gate.ts` example blocks by default when `!ctx.hasUI`. Extensions run in-process with the same OS permissions. Isolation is delegated to Docker, Docker Sandboxes, NVIDIA OpenShell, or the Gondolin micro-VM extension. MCP is built in. Project trust gates loading of `.pi/*` resources; headless modes cannot show the trust prompt (`--approve`/`--no-approve` or `defaultProjectTrust`).
- Model providers: pi.dev claims "15+ providers". Provider modules in source include `anthropic`, `openai`, `openai-codex`, `google`, `google-vertex`, `amazon-bedrock`, `azure`, `openrouter`, `github-copilot`, `mistral`, `deepseek`, `groq`, `together`, `vercel-ai-gateway`, and others, plus a `faux` test provider. OpenAI-, Anthropic-, or Google-compatible endpoints (Ollama, LM Studio, vLLM, proxies) are added via `~/.pi/agent/models.json`. Credentials: `--api-key`, `auth.json` via `/login`, `models.json`, then provider env vars or ambient cloud credentials. The exact runtime provider set is unverified (directory listing used as proxy).
- License and maturity: MIT. Current release 1.1.0 (npm and GitHub, 2026-10-07); 1.0.0 on 2026-10-01; 1.0.3 and 1.0.4 on 2026-10-05. The `[Unreleased]` changelog already lists a breaking change. `@earendil-works/pi-durable` is labelled experimental. GitHub on 2026-10-11: 114302 stars, 14553 forks, 322 open issues. New-contributor issues and PRs are auto-closed by default. Security stance: the local user account and its writable files are inside Pi's trust boundary. Install telemetry defaults on (`PI_TELEMETRY=0` disables).
- Not verified: no command was executed; SDK method signatures; whether any JSON-schema output flag exists; runtime provider set; the "Pi 1.0" post is known only via a fetch summary.
