## Question

What does Claude Code expose for being driven by another program? Capture: headless/non-interactive mode and its flags; structured output formats; the Agent SDK and what it offers beyond the CLI; session persistence and resume; permission modes and sandboxing options; whether it needs a PTY for interactive use; how it behaves inside a container or microVM. Primary sources only: official docs.

## Context

Findings branch: `research/claude-code` (never merged). Findings file on that branch: `docs/research/claude-code.md`.

## Answer

- Headless mode: `claude -p` / `--print` runs non-interactively, reads the prompt from the argument or stdin (stdin capped at 10MB), exits 0 on success and non-zero on failure. `--bare` skips auto-discovery of hooks, skills, commands, subagents, plugins, MCP servers, auto memory, and CLAUDE.md; the docs call it "the recommended mode for scripted and SDK calls" and say it "will become the default for `-p`". Bare mode never reads OAuth credentials or `CLAUDE_CODE_OAUTH_TOKEN`; it needs `ANTHROPIC_API_KEY` or an `apiKeyHelper`. `-p` rejects `--bg`. SIGTERM exits 143 and leaves the turn unfinished; SIGINT ends the turn.
- Flags for driving the CLI: `--output-format text|json|stream-json`, `--input-format text|stream-json`, `--json-schema`, `--include-partial-messages`, `--include-hook-events`, `--max-turns`, `--max-budget-usd`, `--allowedTools`, `--disallowedTools`, `--tools`, `--permission-mode`, `--permission-prompt-tool`, `--permission-prompts host|none`, `--restricted`, `--system-prompt(-file)`, `--append-system-prompt(-file)`, `--mcp-config`, `--strict-mcp-config`, `--agents`, `--settings`, `--setting-sources`, `--add-dir`, `--model`, `--continue`, `--resume`, `--session-id`, `--fork-session`, `--no-session-persistence`. `claude --help` does not list every flag.
- Structured output: `json` returns `result`, `session_id`, and `total_cost_usd` (a client-side estimate). `stream-json` is newline-delimited JSON: `system/init` first (with `session_id`, `tools`, `mcp_servers`, `model`, `capabilities`), `stream_event` partials, `system/api_retry`, `system/permission_denied`, `assistant`/`user` messages with `parent_tool_use_id`, and a final `result` line. `--json-schema` places validated output in `structured_output`. `--input-format stream-json` accepts newline-terminated JSON lines on stdin. Unverified: that CLI `json` equals the SDK `SDKResultMessage` field for field; whether `--verbose` is mandatory for `stream-json`; the exact stdin line shape (the findings infer the SDK's `{"type":"user","message":{...}}` form).
- Agent SDK runtime: TypeScript `@anthropic-ai/claude-agent-sdk` (Node.js 18+) and Python `claude-agent-sdk` (Python 3.10+). Both bundle a native `claude` binary pinned to the SDK version. The SDK "spawns and supervises a `claude` CLI subprocess" and "talks to it over stdio"; one session is one subprocess; "The subprocess itself does not listen on the network." For other languages the docs say to run the CLI with `-p --output-format json`. Third parties may not offer claude.ai login; use API keys.
- SDK beyond the CLI: `canUseTool` permission callback (invoked only when the flow would prompt), in-process hooks (`PreToolUse`, `PostToolUse`, `Stop`, `PermissionRequest`, and more), in-process MCP tools (`createSdkMcpServer`), programmatic subagents, `spawnClaudeCodeProcess` "to run Claude Code in VMs, containers, or remote environments", `SessionStore` transcript mirroring for cross-host resume, `interrupt()`, `setPermissionMode()`, `setModel()`, `streamInput()`, `prewarm()`. Hosting guidance: 1 GiB RAM, 5 GiB disk, 1 CPU per agent as a starting point; no top-level session timeout; multi-tenant isolation via `settingSources: []`, per-tenant `CLAUDE_CONFIG_DIR` and `cwd`.
- Sessions: JSONL at `~/.claude/projects/<project>/<session-id>.jsonl`, with `<project>` derived from the working directory path. The entry format "is internal to Claude Code and changes between versions". `--resume <id>` searches the current project and its worktrees, then "every other project on this machine"; it also accepts a transcript path. `CLAUDE_CONFIG_DIR` relocates storage; `CLAUDE_CODE_PROJECT_DIR_NAME` names the project directory for embedding hosts. Resume restores history, model, and agent; `--mcp-config`, `--settings`, `--plugin-dir`, `--add-dir` must be passed again. Cross-host persistence requires the SDK `SessionStore`; local transcripts do not survive a container restart or node move.
- Permission modes: `default`, `acceptEdits`, `plan`, `auto` (classifier), `dontAsk` (anything that would prompt is denied), `bypassPermissions` (`--dangerously-skip-permissions`). Deny rules apply in every mode. The starting mode for `-p`/SDK depends on feature-flag fetch and version; the docs advise passing a mode explicitly. `--dangerously-skip-permissions` refuses to start as root or under `sudo` on Linux and macOS; the check "is skipped automatically inside a recognized sandbox" (term undefined; unverified). Docs say to run it only inside a container, VM, or the sandbox runtime.
- Sandboxing: the built-in Bash sandbox uses Seatbelt on macOS and `bubblewrap` plus `socat` on Linux/WSL2; it is off by default, covers shell commands only, and routes network through a host-side proxy whose domain allowlist starts empty. Inside an unprivileged container it needs `enableWeakerNestedSandbox: true`; `docker` is incompatible with it. The whole-process `@anthropic-ai/sandbox-runtime` is "a beta research preview". Native Windows runs unsandboxed.
- PTY: no page states in so many words that `-p` needs no TTY. The findings infer, from the stdio-driven SDK, the pipe examples, and the error pages, that `-p` runs without a PTY and only the interactive UI needs one. Interactive mode reads keystrokes from `/dev/tty` and needs stdout to be a terminal; when stdout is redirected, `claude` falls back to the same mode as `claude -p`. `claude agents` "requires an interactive terminal".
- Containers and microVMs: Claude Code runs in any Docker or OCI image. Docs recommend a non-root user, `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`, `DISABLE_AUTOUPDATER=1`, a volume at `~/.claude` with `CLAUDE_CONFIG_DIR`, and pinning with `npm install -g @anthropic-ai/claude-code@X.Y.Z`. Required egress: `api.anthropic.com`, plus `claude.ai`/`claude.com`/`platform.claude.com` for OAuth; "Claude Code does not support SOCKS proxies". The npm package downloads a native binary that does not use Node.js at runtime. System requirements: macOS 13.0+, Ubuntu 20.04+, Debian 10+, Alpine 3.19+, 4 GB+ RAM. Docs name Firecracker microVMs and gVisor as isolation options and describe a vsock-to-host-proxy pattern, but document no microVM-specific Claude Code behaviour (unverified; docs treat a microVM as an ordinary Linux host).
- Authentication for automation, in precedence order: cloud-provider env (`CLAUDE_CODE_USE_BEDROCK|VERTEX|FOUNDRY`), `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_API_KEY` ("always used when present" under `-p`), `apiKeyHelper`, `CLAUDE_CODE_OAUTH_TOKEN` (from `claude setup-token`, one-year, Pro/Max/Team/Enterprise only), then OAuth login. `ANTHROPIC_BASE_URL` can route through a key-injecting proxy.
